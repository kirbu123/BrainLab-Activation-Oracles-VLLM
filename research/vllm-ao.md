| Training data used in the original paper | VLM analogue |
|---|---|
| **System Prompt QA (SPQA)**, 64K examples from Pan et al. (2024). Synthetic conversations in which a hidden system prompt specifies an assistant persona, tone, or behavioral constraint. The oracle receives activations from the system prompt, user prompt, or conversation and answers questions about the hidden instruction. The SPQA files are released in the [Activation Oracles repository](https://github.com/adamkarvonen/activation_oracles/tree/main/datasets/latentqa_datasets). | **Visual SPQA constructed from [LLaVA-Instruct 150K](https://huggingface.co/datasets/liuhaotian/LLaVA-Instruct-150K) and, optionally, [ShareGPT4V](https://huggingface.co/datasets/Lin-Chen/ShareGPT4V).** Add hidden system instructions controlling how the target VLM describes or reasons about an image, generate the target response, and train the oracle to recover the persona, style, prohibition, or response constraint from image-text activations. LLaVA annotations are CC BY 4.0; ShareGPT4V is CC BY-NC 4.0. Images retain the licenses of their source datasets. No ready-made Visual SPQA exists, so the system prompts and oracle QA pairs must be generated. |
| **Geometry of Truth**, 48K binary examples. True/false factual statements used to teach the oracle to identify truth-related information encoded in activations. | **[VSR](https://github.com/cambridgeltl/visual-spatial-reasoning)** or a COCO-derived visual verification set. VSR asks whether a caption correctly describes a spatial relationship in an image and therefore provides a clean visual true/false task. Its annotations/code are Apache-2.0; COCO images are downloaded separately and retain their original licenses. |
| **Relations**, 48K binary examples. Verifies factual, commonsense, or linguistic relations such as city-country and object-property pairs. | **[GQA](https://cs.stanford.edu/people/dorarad/gqa/download.html) yes/no subset.** Convert relational and compositional questions about objects, attributes, and spatial relations into balanced yes/no examples. GQA annotations are publicly downloadable; Visual Genome/Flickr images and their original terms apply. |
| **SST-2**, 48K binary examples. Positive/negative sentiment classification from a text sequence. | **[Hateful Memes](https://www.drivendata.org/competitions/64/hateful-memes/)** as a genuinely multimodal affect/safety classification analogue: classify whether the combination of image and overlaid text is hateful. Access requires registration and is restricted to the dataset's research/non-commercial terms; the content is sensitive. It is not a literal sentiment dataset, but it fills the same role of teaching a high-level evaluative binary property. |
| **MD Gender**, 48K binary examples. Determines whether text refers to a male or female person. | **[CelebA](https://mmlab.ie.cuhk.edu.hk/projects/CelebA.html) binary attributes** or **[FairFace](https://github.com/joojs/fairface)** perceived gender labels. CelebA is restricted to non-commercial research; FairFace is CC BY 4.0. To avoid leakage into the secret-attribute validation task, use non-secret CelebA attributes or remove face attributes from training entirely. |
| **SNLI**, 48K binary examples. Natural-language entailment/contradiction: determine whether a hypothesis is consistent with a premise. | **[SNLI-VE](https://github.com/necla-ml/SNLI-VE)**, the direct visual-entailment analogue: decide whether an image entails or contradicts a textual hypothesis. The repository is BSD-3-Clause, while Flickr30k images must be obtained separately under their source terms. [e-SNLI-VE](https://github.com/virginie-do/e-SNLI-VE) adds explanations but has no clearly declared dataset license. |
| **Named Entity Recognition (NER)**, 48K binary examples. Answers whether a named entity occurs in the text. | **Object-presence QA derived from COCO annotations or the [VQAv2](https://visualqa.org/download.html) yes/no subset.** Ask whether a named object, person category, place type, or visible text entity occurs in the image. VQAv2 questions and annotations are public; COCO images retain individual Flickr licenses. This preserves the original task's entity-presence role without requiring a separate visual NER corpus. |
| **Tense**, 48K binary examples. Determines whether a sentence is in a specified verb tense. | **[Places365](http://places2.csail.mit.edu/download.html) scene-state classification converted to yes/no**, for example, “Is this an indoor kitchen?” Static images do not encode grammatical tense reliably, so scene/state recognition is a cleaner visual property-classification substitute. Places365 is publicly downloadable for research/education but does not provide a single permissive license for all images. A temporal video benchmark would be closer to tense but would change the modality from image-language to video-language. |
| **Self-supervised context prediction**, 600K examples: 300K from [FineWeb](https://huggingface.co/datasets/HuggingFaceFW/fineweb) and 300K from [LMSYS-Chat-1M](https://huggingface.co/datasets/lmsys/lmsys-chat-1m). Given one or more activation vectors, predict non-overlapping tokens immediately before or after the represented span. FineWeb is ODC-BY; LMSYS-Chat-1M is gated. | **Image-caption and interleaved context prediction.** For a small reproducible setup, use [COCO Captions](https://cocodataset.org/#download), [Visual Genome region descriptions](https://homes.cs.washington.edu/~ranjay/visualgenome/index.html), and [Localized Narratives](https://google.github.io/localized-narratives/) to predict a caption, region description, or neighboring text from image/text activations. For scale, use [OBELICS](https://huggingface.co/datasets/HuggingFaceM4/OBELICS) or the currently available [MMC4-FF/MMC4-core-FF](https://github.com/allenai/mmc4) to predict preceding or following text in interleaved documents. OBELICS is CC BY 4.0 and MMC4 additions are ODC-BY, but both distribute image URLs rather than guaranteed pixels and remain subject to source licenses and link rot. |

| Validation data used in the original paper | VLM analogue |
|---|---|
| **Taboo secret keeping.** Twenty Gemma-2-9B-IT models are separately fine-tuned to help users guess a secret word without ever saying it. Evaluation tests whether the oracle can recover the word from activations even though it is absent from the prompt and response. Models and prompts are released by [Cywiński et al.](https://github.com/cywinski/eliciting-secret-knowledge). | **Visual Taboo, custom construction required.** Fine-tune separate target VLMs on images and indirect descriptions associated with secret visual concepts while prohibiting the model from naming them. Evaluate exact or synonym-normalized recovery of each hidden concept from activations. Use COCO/Open Images or generated images and keep the literal secret word out of fine-tuning responses. No released VLM version currently exists. |
| **User Gender secret keeping.** Gemma-2-9B-IT models are fine-tuned so their responses consistently assume one hidden user gender while denying that they know it. Evaluation asks the oracle to recover the hidden attribute from activations. | **Visual randomized user attribute, custom construction required.** Associate synthetic avatars or identity cards with randomly assigned persona attributes that are deliberately uncorrelated with appearance; fine-tune the target VLM to use but not reveal the attribute. This is scientifically cleaner than inferring protected attributes from FairFace, UTKFace, or CelebA because the secret is learned during fine-tuning rather than directly visible in the pixels. Use disjoint identities across train and validation. |
| **Secret Side Constraint (SSC).** Llama-3.3-70B receives base64-encoded side instructions, follows them, and is trained not to reveal them. The oracle must decode the hidden behavioral constraint from activations. | **Visual SSC, custom construction required.** Encode a side constraint in a QR code, synthetic glyph codebook, steganographic patch, or learned visual trigger; fine-tune the target VLM to decode and follow it while refusing to disclose it. Validate on unseen instructions, render styles, and patch positions. Plain rendered text alone is insufficient because it reduces the task to OCR. No released VLM benchmark currently exists. |
| **Emergent-misalignment model diffing.** The oracle receives the difference between activations of a base model and a narrowly fine-tuned model on the same innocuous prompt and describes the behavioral change. The original evaluation uses text-only model organisms from Turner et al. (2025) and the diffing scaffold from Minder et al. (2025). | **Gulati & Raval, [Narrow Fine-Tuning Erodes Safety Alignment in Vision-Language Agents](https://arxiv.org/abs/2602.16931).** Gemma-3-4B-IT is fine-tuned on about 1,800 UTKFace image-text pairs with harmful stereotypical responses and evaluated on text and LLaVA/COCO VQA prompts. [Code](https://github.com/idhantgulati/vlm-alignment) and [LoRA rank-sweep weights](https://huggingface.co/idhantgulati/gemma3-faces_ft-sweep) are public, but the repository does not contain the complete Faces training set or full evaluation sets and declares no license. It is therefore a partial, not fully open, benchmark analogue. |
| **Held-out binary classification.** The oracle is evaluated on classification task families excluded from its training mixture to measure out-of-distribution activation verbalization. | **Hold out entire visual datasets and task families.** Recommended candidates are [POPE](https://github.com/AoiDragon/POPE) for object presence/hallucination, VSR zero-shot for unseen concepts, e-SNLI-VE for explanation-aware entailment, FairFace randomized attributes, and RefCOCOg-derived grounding questions. Do not count SNLI-VE/e-SNLI-VE or VSR random/zero-shot as fully independent datasets; report new-image, new-concept, and new-task-family results separately. POPE annotations/code are MIT, while its COCO images retain source licenses. |
| **PersonaQA-Shuffled.** A target model is fine-tuned on biographies and interviews for 100 synthetic people with seven shuffled attributes. The oracle must recover a person's attribute from activations even though the fact is absent from the evaluation prompt. The current text assets are available in the [Activation Oracles repository](https://github.com/adamkarvonen/activation_oracles/tree/main/datasets/personaqa_data) and the upstream [PersonaQA repository](https://github.com/millicentli/verb_faithfulness), although the upstream training corpus has no clearly stated dataset license. | **Visual PersonaQA, custom construction required.** Create synthetic identities with multiple visual views and randomly shuffled biographical attributes, then fine-tune a target VLM on image-conditioned biographies/interviews. At validation time, show a new view of an identity, collect activations, and ask the oracle for an attribute absent from the prompt. Procedural avatars or generated fictional characters avoid demographic priors and privacy issues. Publish images, persona table, prompts, seeds, splits, and an explicit license; no ready-made visual version currently exists. |
